# Audio filter design — specify the behavior before choosing coefficients

## Activate when

Use for low/high/band-pass or reject filters, EQ/notches, FIR versus IIR decisions, anti-alias/reconstruction requirements, digital filter corner or Q interpretation, stable second-order-section (SOS) implementation, group delay/ringing, or verifying a proposed filter. Read the [filter-design and numerical contract](references/FILTER_DESIGN_CONTRACT.md) and [frozen-golden provenance](../../tests/fixtures/AUDIO_FILTER_DESIGN_EXTERNAL_GOLDENS.md) before citing test evidence.

Load [audio-resampling](../audio-resampling/SKILL.md) when the task is *sample-rate conversion* rather than equal-rate filtering; [audio-timebase-sync](../audio-timebase-sync/SKILL.md) for stream clocks; [audio-sample-formats](../audio-sample-formats/SKILL.md) for PCM quantization, and [audio-dsp-test-fixtures](../audio-dsp-test-fixtures/SKILL.md) for synthetic signals. Reuse [math-complex-numbers](../math-complex-numbers/SKILL.md) for phasors/poles, [math-numerical-analysis](../math-numerical-analysis/SKILL.md) for conditioning/precision, [math-dimensional-analysis](../math-dimensional-analysis/SKILL.md) for Hz/sample/time conversion, and [math-verification](../math-verification/SKILL.md) for oracle independence **only when needed**. Do not duplicate or preload the entire mathematics curriculum.

## Procedure

1. **Write a falsifiable target before designing.** Record exact sample rate, input and output channels and sample representation; topology, purpose and passband(s)/stopband(s) in Hz; permissible passband deviation and stopband attenuation in dB; transition region; phase/group-delay and latency budget; amplitude headroom; response to transient/step signals; numerical dtype and acceptable CPU/memory cost. Distinguish analog design frequency, digital cutoff, -3 dB corner, -6 dB window-method cutoff, and crossover frequency. Never describe an arbitrary design number as a proven response threshold.
2. **Choose FIR versus IIR for the engineering constraints.** A symmetric causal Type-I FIR offers **constant group delay (N−1)/2 input samples** away from response zeros, at N multiply-accumulates/sample per channel in this reference. Narrow transitions can require many taps, adding latency and memory; overshoot/ringing and boundary transients remain possible. IIR biquads can offer efficient, low-latency shaping, but generally have frequency-dependent phase delay, recursive state and greater sensitivity to coefficient quantization. A high-Q section can peak **above** 0 dB without any error. Be explicit when trading one property for another.
3. **FIR design in this small oracle.** Use [the reference](scripts/reference_filter_design.py) for odd 5–129-tap windowed-sinc lowpass/highpass/bandpass/bandstop using Hann, Hamming or Blackman windows. Apply spectral inversion and band-edge combinations with consistent odd-tap center, normalize by DC (LP/BS), Nyquist (HP), or band center (BP). The prescribed cutoff is the ideal sinc **half-amplitude (roughly −6 dB)** edge, *not* the -3 dB Butterworth corner. Finite windows produce leakage, transition width and passband ripple; even nominal stopbands can have nonzero DC leakage. Recompute and measure the actual coefficients rather than infer specifications from the window name.
4. **IIR design in this small oracle.** Use normalized W3C/RBJ biquad sections for lowpass, highpass, notch, and peaking EQ. Declare sample rate, Hz, **dimensionless Q** (not octave bandwidth), and peaking gain in dB. The reference supports Q 0.2–20, peaking gain ±24 dB and up to four SOS stages. With Q=1/√2, an isolated LP/HP section has **−3.0103 dB at its corner**, unlike the windowed FIR convention. Normalize a0=1; model H(z)=(b0+b1 z^-1+b2 z^-2)/(1+a1 z^-1+a2 z^-2). Inspect every pole and reject sections at/near the unit circle. Do **not** blindly form a high-order direct-form polynomial when SOS would be safer.
5. **Verify the implemented response, not just the recipe.** At a stated frequency grid compute complex H(e^{jω}), magnitude (20 log10|H|), phase and local group delay −d arg(H)/dω. A magnitude null makes phase/group delay undefined; do not report an invented number or unwrap discontinuities blindly. [Sampled-band checking](scripts/reference_filter_design.py) reports passband min/max and worst sampled stopband value; **passing a finite grid is not a continuous-band guarantee**. Evaluate endpoint/edge frequencies, multiple pass/stopband frequencies and an independently implemented frequency-response calculation before calling a design acceptable.
6. **Audit the signal path.** Check impulse and step response, expected causal delay/ringing, warm-up and zero initial conditions, coherent amplitude gain/peak overshoot, anti-phase and channel independence, and boundaries after seeking or format/rate changes. Filtering a stream preserves **frame count and sample rate** here, but latency does not vanish. Do not silently clamp ±1, normalize by hand after computing EQ, or claim that sample peaks certify true peaks. Keep proper device clock and channel semantics in their respective skills.
7. **Protect finite precision and stream state.** Confirm pole radius, then quantize coefficients to the target representation and recheck **poles and response**. Quantization here is a nearest-even fractional-bit **coefficient** demonstration, not production fixed-point overflow/limit-cycle proof. SOS processing uses a per-channel transposed direct-form II state. The bounded reference validates inputs and calculates each callback in a temporary state, committing only if fully finite; gaps, overlaps, nonfinite data and numeric overflow reject atomically. Require new never-reused epochs for seeks and reconfiguration. Smooth real-time coefficient automation, state transfer, crossfades, denormal suppression and lock-free operation require separate application engineering.
8. **Falsify with independent cases.** Run [37 focused standard-library tests](../../tests/test_audio_filter_design_reference.py) for W3C 3 dB versus FIR 6 dB conventions, windows and spectral inversion, exact symmetry/delay, frozen external SciPy FIR/Butterworth coefficients, notch/EQ gain, SOS product response, pole rejection, Q resonance, coefficient quantization, phase nulls, sampled-band *pass and deliberate failure*, causal impulse/step behavior, >2^53 timestamps, channel isolation, callback partition equivalence, bad inputs, atomic overflow and resets. Optionally run [the live SciPy differential](scripts/check_scipy_filter_design.py) and record **actual** versions/counts. SciPy shares filter-design assumptions with this oracle but is an independent numerical backend; matching values cannot prove a shared design is optimal or production-safe.
9. **Declare acceptance boundaries.** A filter is not finished merely because its coefficients are valid or its unit tests pass. Confirm performance across supported sample rates, devices and channel configurations; response tolerance between sample-grid points; transient audibility, time-varying parameter changes, quantized/denormal behavior, CPU under callback load and calibration as needed. Mark the difference between a verified bounded educational oracle and a production audio processing component.

## Reference verification

From the Kestrel root:

```sh
python3 tools/validate_seed.py
python3 -m unittest discover -s tests -v
python3 skills/audio-filter-design/scripts/check_scipy_filter_design.py --seed 20261104 --cases 24
```

The first two commands need the Python standard library only; the last is optional and needs NumPy/SciPy installed separately. Do not claim it ran in ordinary GitHub CI. The Python reference handles **2–384 kHz Fraction rates, 1–8 channels, up to 256 frames per callback, FIR ≤129 odd taps, or 1–4 normalized biquad sections**. The sampled-frequency-grid checker has a separate bounded density. None of this establishes calibrated device, time-varying, audible, or realtime behavior.

## Primary sources

- [W3C Audio EQ Cookbook (2021 Note)](https://www.w3.org/TR/audio-eq-cookbook/) — Robert Bristow-Johnson's bilinear-transform biquad coefficient conventions; not a normative W3C recommendation.
- [SciPy firwin](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.firwin.html) — window method, Type-I/II FIR, specified half-amplitude cutoff.
- [SciPy group_delay](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.group_delay.html) — negative derivative of unwrapped phase; singularities.
- [SciPy signal reference](https://docs.scipy.org/doc/scipy/reference/signal.html) — FIR/IIR/SOS design and independent numerical analysis APIs.
